🖥️ ProgrammingHacks（プログラミング）

基礎スキル

  • HTML/CSSの基本構造を理解している

    • → 現場の案件の90%以上がHTML/CSSベース。ここが全ての土台になる

  • レスポンシブデザイン（スマホ対応）が実装できる

    • → 2025年現在、アクセスの75%以上がスマホ。「スマホ対応できません」は即不採用

  • JavaScriptの基本文法（変数・関数・条件分岐・ループ）を理解している

    • → LP案件でも「ボタンクリックでメニューを開く」程度のJSは必須

  • jQueryまたはVanilla JSでDOM操作ができる

    • → 既存サイトの修正案件ではjQueryが使われていることが多い。読めるだけでOK

実務スキル

  • 既存のWebサイトのデザインを見て、同じものをコーディングできる

    • → 案件の大半は「このデザインの通りにコーディングして」。模写力＝案件対応力

  • WordPressの基本的なカスタマイズができる

    • → 全Webサイトの43%がWordPress。触れるだけで案件の幅が一気に広がる

  • ブラウザの開発者ツール（DevTools）を使ってデバッグできる

    • → 「表示がずれてます」と言われた時に原因を特定できるかどうかが分かれ目

  • GitHubの基本操作（clone, commit, push）ができる

    • → チーム開発の案件では必須。個人案件でも「Git使えます」で信頼度UP

案件獲得の最低ライン

  • LPコーディングのサンプルを1つ以上作成した

    • → 「実績がない」のと「サンプルがない」は別。サンプルは今日から作れる

  • ポートフォリオサイトを公開している

    • → GitHub PagesやNetlifyで無料公開できる。見せ方が9割

🎯 最短で身につける方法: ProgrammingHacksの基礎編（動画約20本）を1日2本ペースで消化 → 10日で土台完成。並行してLP模写を1本作れば、そのままポートフォリオに。

🎬 MovieHacks（動画編集）

基礎スキル（必須5項目）

  • テロップの挿入・装飾ができる

    • → 視聴者の目を引く最重要要素。フォント選び＋色使い＋位置の3つを押さえる

  • カット編集（不要部分の削除・繋ぎ）ができる

    • → 「えーっと」「あのー」を消すだけで動画のクオリティが段違いに上がる

  • BGMの挿入・音量調整ができる

    • → BGMは「聞こえるか聞こえないか」の音量がベスト。大きすぎは素人の証

  • 効果音（SE）の挿入ができる

    • → テロップ出現時の「ポン」「シュッ」で視聴維持率が平均12%向上するデータあり

  • 画像・図解の挿入ができる

    • → トーク系動画では画像挿入があるだけで「プロっぽい」と感じてもらえる

実務スキル

  • Premiere Pro（またはDaVinci Resolve）の基本操作を理解している

    • → 案件の8割がPremiere Pro指定。DaVinci Resolveは無料で練習に最適

  • テンプレートを使って10分の動画を2時間以内に編集できる

    • → 時給換算で2,500円以上を確保するための最低ライン

  • サムネイル画像の作成ができる（Canva or Photoshop）

    • → 「編集＋サムネセット」で提案すると単価が1.5〜2倍になる

  • 書き出し設定（解像度・ビットレート）を理解している

    • → YouTube推奨設定を知っているだけでOK。間違えるとクレームの元

案件獲得の最低ライン

  • YouTube動画の編集サンプルを1本以上作成した

    • → 好きなYouTuberの動画を「勝手に編集」して練習作品にするのが王道

  • ポートフォリオ（サンプル動画のリンク集）を用意している

    • → Googleドライブで限定公開リンクを作り、提案文に貼るだけ

🎯 最短で身につける方法: MovieHacksの基礎5項目は動画10本程度。1週間で完了 → すぐにサンプル制作。迫さんも「この5つができればYouTube編集案件は受けられる」と断言。

STEP 6：初案件を納品する（10〜14日目）

やること

受注した案件を納品する。ここが一番大事なSTEP。

案件進行の流れ

1. 受注確定 → 条件・納期を確認
2. 不明点を質問 → 作業開始前に疑問をゼロにする
3. 作業開始 → 途中経過を共有（50%時点で一度確認）
4. 初稿提出 → 修正依頼を受ける
5. 修正対応 → 最終確認
6. 納品完了 → 評価をもらう

初案件で意識すべき3つのこと

  1. レスポンスの速さ — メッセージは即返信。これだけで信頼度が段違い
  2. 納期厳守 — 余裕を持ったスケジュールを提示し、前倒しで納品する
  3. 丁寧なコミュニケーション — 進捗報告をこまめにする

💼 初案件あるある失敗談と対処法

実際の受講生から聞いた「初案件のやらかし」とその対処法です。事前に知っておくだけで、同じミスを避けられます。

① 「思ったより難しい…」パニック

  • 状況：受注したけど、想定より技術的に難しくて手が止まる
  • 対処法：まず伴走支援メンバーに即相談。「分からないけど何とかしたい」という姿勢を見せれば、必ず助けてもらえる
  • 最悪の場合：「今回お金は受け取りませんので、最後まで納品だけさせてください」で誠意を見せる。大きなトラブルにはならない

② 修正が3回以上来て心が折れる

  • 状況：「ここ変えて」「ここも変えて」「やっぱり最初の方が…」のループ
  • 対処法：受注時に「修正は2回まで」と明記しておく（テンプレート集のメッセージ参照）。修正回数は事前合意が鉄則
  • マインド：修正は「ダメ出し」ではなく「クライアントの好みを学ぶチャンス」

③ 納期ギリギリになって焦る

  • 状況：作業量を見誤って、締め切り前日に徹夜コース
  • 対処法：提示する納期は「自分が思う必要日数 × 1.5倍」にする。余裕があれば前倒し納品 → クライアント大喜び
  • 鉄則：「間に合わないかも」と思った瞬間にすぐ連絡。ギリギリまで黙っているのが最悪のパターン

④ 単価が安すぎて時給100円になる

  • 状況：1本3,000円で受けたのに、作業に20時間かかった…
  • 対処法：初案件は「実績づくり」と割り切る。2件目からは作業時間を記録して、時給を計算してから受注可否を判断する

🧠 メンタルブロック5選と突破法

案件獲得を阻む最大の敵は、スキル不足ではなくメンタルブロックです。以下は受講生が最もよくハマる5つの壁と、突破した人たちのリアルな声です。

ブロック①「まだスキルが足りない気がする…」

突破法：迫さんも最初のプログラミング案件は「クイズアプリを作れる」程度の技術しかなかった。それでも学習塾のアプリ開発案件を取り、18,000円で受注して1件目の営業で即成約。技術が成熟してからなんて待てない。最低限できれば、飛び込んでいい。

「最悪、本当に謝って"今回お金受け取らないんでただ最後までやらせてください"って言ったら大きなトラブルになることなんかない」── 迫 佑樹

ブロック②「応募しても返信が来ない…向いてないのかも」

突破法：返信率10〜15%が普通。10件送って1件返事が来ればいい方。300件応募してやっと初案件を取り、今は月50万稼いでいる受講生がいる。500件応募してもダメだった人が、最終的に100万フォロワーのインフルエンサーになった事例も。「数が足りてるか？」がまず最初のチェックポイント。

ブロック③「お金をもらっていいレベルじゃない…」

突破法：これは「完璧主義の罠」。先を行っている先輩がいる環境にいると「完璧じゃなくてもいける」と気づける。スキルハックスのコミュニティでは、日報を通じて他の受講生の進捗が見える。基準値が上がると「自分もやっていいんだ」と思える。

「完璧じゃないとお金なんかもらっちゃいけないっていうメンタルブロック…これは先を行ってる先輩がいるからこそ脱却できる」── 迫 佑樹

ブロック④「一人でやってると不安で続かない…」

突破法：これは受講生の声でも一番多い。独学で挫折した方がスキルハックスに入った理由の第1位が「相談できる環境が欲しかった」。ある受講生は「プログラミングスクールで先生と相性が合わなくて辞めた → 独学で行き詰まった → スキルハックスで仲間ができたことで、独学では絶対超えられなかった壁を超えた」と語っています。

「環境を整えてください。私の性格と能力では多分1人ではできなかったと思います」── 受講生インタビューより

ブロック⑤「副業バレが怖い…会社に知られたくない」

突破法：

  • 確定申告で「住民税を普通徴収（自分で納付）」にチェックすれば、会社には通知されない
  • クラウドソーシングのプロフィールにはニックネーム＋本名なしでも活動可能
  • 顔出しなしでも案件は取れる（ポートフォリオで判断されるため）
  • それでも心配なら、伴走支援メンバーに個別相談してください
