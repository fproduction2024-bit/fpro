Section 02

② 現状課題の整理

なぜ今、この施策が必要なのか。現状の構造的な問題を整理します。

⚠️ 現在の構造的な課題

課題詳細インパクト
単価の高さ コンサルタントの時給が〜と発注側から見て高い 案件を依頼しづらい状況。仕事が回らない
フォーマット未整備 構築の内容・価格・手順が担当者ごとにバラバラ 再現性がない。外部から使いづらい
属人化 一部の優秀な人に仕事が集中。他は動けていない スケールしない。リスクも高い
教育コストの無駄 プロラインが教育しても雇用関係がなく資産化しない 教育投資の回収ができていない
根本的な問題： 現在の構造は「プロラインコンサルタントを抱える」モデル。 本来目指すべきは「プロラインが基盤を整備し、外部プレイヤーが自律的に動く」モデルです。
Section 03

③ ルートA・B の設計

構築代行プレイヤーが動きやすくするための2つのルートを設計します。 両ルートは排他的ではなく、並行して進めることができます。

ルート A 案件取得者 × プロライン仲介・支援
基本的な考え方：
すでに外部から案件を取れる人（コンサルタント等）が受注し、 その一部の実装・設定作業をプロライン側が支援できる体制を作る。

プロラインの役割：
発注された実装・設定を自社アカウント内で実施。 コンサルタントと顧客の間を結ぶ実装パートナーとして機能する。

メリット：
既存の案件獲得チャネルをそのまま活かせる。 営業コストなしでプロラインが実装収益を得られる。
ルート B 誰でも使えるフォーマット整備
基本的な考え方：
プロライン本体が構築の「型」を整備し、 「何を用意すれば案件が作れるか」を明確化して提供する。

必要な素材さえあれば誰でも実装できる：
動画と配信文面があれば、残りの実装部分（フォーム・シナリオ等）を 標準フォーマットで進められるようにする。

メリット：
1人への依存がなくなる。プレイヤーが増えるほどスケールする。
Phase1ではルートBを先に整備するのが現実的です。 フォーマットが整って初めて、ルートAで仲介が機能するようになります。
Section 04

④ フォーマット整備の内容（ルートB）

「動画と配信文面があれば、あとは実装できる」状態を作るために 標準化すべき実装項目を定義します。

標準化する実装項目一覧

✓
フォーム
作成・接続・自動応答の標準設定
✓
コンテンツページ
テンプレートベースで即作成可能な構成
✓
シナリオ構築
ステップ別の配信設計の型（AI活用可）
✓
メッセージ設定
文面テンプレート＋変数設定の標準化
✓
必要最低限の画像整備
バナー・アイコン等の最小セット定義
✓
設定導線チェックリスト
抜け漏れ防止のための確認フロー
AI活用方針： 文章作成・シナリオ文面・HTMLテンプレート生成はAIを前提として実施。 人間は最終確認と設定作業に集中することで、最小工数で案件を回せる体制にする。

整備の優先順位（案）

優先度項目難易度目安工数
★★★シナリオ構築テンプレート（AI＋型）中3〜5日
★★★フォーム標準設定マニュアル低1〜2日
★★☆コンテンツページテンプレート中3〜5日
★★☆メッセージ文面テンプレート集低2〜3日
★☆☆画像最小セット（バナー等）高要検討
★☆☆設定チェックリスト低1日
⚠️ 注意： 画像・コンテンツページのリッチ化は工数対効果を必ず確認してから着手すること。 まずは「必要最低限で案件が完成する状態」を先に整備し、後から品質を上げる方針が現実的。
Section 05

⑤ 価格・単価設計の見直し

時給型からパッケージ型への移行により、 発注側が依頼しやすく、プレイヤー側も件数を増やしやすい体制を作ります。

💡 基本的な考え方

高単価な時給型（〜/時間）で抱えるのではなく、
型化・標準化した作業を、より実務的なパッケージ単価で回せるようにする。

パッケージ価格設計案（※要調整）

プラン 含まれる内容 価格目安
ライトプラン フォーム＋シナリオ＋基本設定のみ
スタンダードプラン ライト＋コンテンツページ＋メッセージ設計
カスタムプラン スタンダード＋画像整備＋コンテンツリッチ化 〜
価格は変数 packagePriceLight / packagePriceStandard / packagePriceCustom で変更できます。 実際の市場価格や競合事例を調査した上で最終決定してください。
  • 発注側のメリット：事前に費用が見えるため稟議・判断がしやすい
  • 構築側のメリット：作業の型が決まると件数をこなしやすくなる
  • プロライン側のメリット：案件の標準化により品質が安定・管理しやすい

Section 08

⑧ 実行スケジュール

初期ヶ月の実行タイムラインです。フォーマット整備を先行し、その後展開・改善を繰り返します。

P1
Phase 1 — 第週以内
フォーマット整備（ルートB基盤づくり）
優先度「★★★」の項目から着手：シナリオテンプレート＋フォーム標準マニュアル
AI活用で文面・テンプレートを高速生成
整備物を社内でレビュー → v1.0を確定
P2
Phase 2 — 第〜5週
パイロット展開（ルートA活用開始）
既存の案件獲得者（ルートA）にフォーマットを使ってもらい実案件で検証
パッケージ価格の実運用テスト・単価調整
フィードバックをもとにフォーマットを改善
P3
Phase 3 — 〜ヶ月
本格展開・プレイヤー増加
対象プレイヤーを人まで拡大
月間案件数件を目標に管理
コンテンツページ・画像整備など残りフォーマットを順次完成させる

🚀 この計画の成功要件

「自社で全部やる」から「基盤を作ってプレイヤーに動いてもらう」への発想転換が鍵。
フォーマットが先、プレイヤー展開が後。 この順番を守ることで再現性のある体制が生まれます。
