# クライアントダッシュボード生成スキル

リッツプロのクライアント案件ごとに、プロジェクト管理ダッシュボード（単一HTML）を生成するスキル。

## 概要

このスキルは `templates/dashboard-template.html` をベースに、クライアント固有の情報を埋め込んで案件別ダッシュボードを生成する。すべての機能が1つのHTMLファイルに収まっており、surge.sh 等の静的ホスティングにデプロイ可能。

お客様カルテの項目構造は、リッツプロのFC本部構築マニュアルが正本。項目を追加・変更する際は必ず `references/fc-manual-structure.md` と突き合わせること。

## ダッシュボードの構成

### サイドバー構成（クライアント目線の4群）

1. **プロジェクト**: ホーム / スケジュール / 議事録 / 成果物
2. **戦略・設計**: お客様カルテ / マニュアル
3. **制作物**: 広告クリエイティブ / 広告運用設計 / LP・Webページ / セミナースライド / 申込み導線
4. **管理**: ログイン情報

サイドバー最下部に担当者カード（Fプロダクション 古橋）を常設。

### プロジェクト管理セクション

| セクション | 機能概要 |
|-----------|---------|
| **ホーム** | プロジェクトホーム。フェーズステッパー（戦略設計→制作→募集準備→募集開始→加盟店開発、クリックで現在フェーズ変更）+ KPIカード4枚（全体進捗% / 進行中タスク・遅延 / 次回MTG / 成果物完了数）+ 次のアクション（最新議事録から自動表示、担当バッジ色分け）+ 成果物進捗バー。すべて他セクションのlocalStorageデータから自動集計（追加入力不要） |
| **お客様カルテ** | 4タブ構成（顧客情報 / ヒアリング① / ヒアリング② / 営業資料）+ 右側スクロールスパイ・セクションナビ（各セクションの入力済みカウント表示、1280px未満は非表示）+ 下部固定保存バー（最終保存時刻・未保存変更インジケータ） |
| **スケジュール** | ガントチャート。月ナビゲーション、タスクCRUD、4種ステータス（未着手/進行中/完了/遅延）+ ステータスフィルタチップ + 今日列のゴールドハイライト + タスク名列の横スクロール固定 |
| **議事録** | CRUD、日付・議事録・動画・NextAction・担当・期限・次回日程。上部に全議事録横断の「未完了のアクション」集約カード（期限超過は赤字）、一覧は縦タイムライン表示（最新ノードはゴールド） |
| **マニュアル** | カード型6件、Markdownエディタ、作成済み/未作成ステータス |
| **成果物** | 2タブ（本部構築12件 / 加盟店開発11件）、チェックリスト |
| **ログイン情報** | パスワード表示トグル、コピー機能、追加/削除 |

### お客様カルテ 詳細構成

#### 顧客情報タブ
- 基本情報: 法人名、フリガナ、代表者名、メール、電話、業種、年商、決算月、SNS
- 関連リンク: LP、スケジュール管理表、本部マニュアル、UTAGE/LINE公式ログイン、アンケートURL、提案書1・2
- 商談動画: 6枠
- セールス用資料: 事例集（営業資料）
- 顧客インタビュー動画: 3枠

#### ヒアリング①タブ（コンセプト設計）
- 戦略設計: 全社/事業/機能/財務戦略 + ビジネスモデル優位性
- ゴール設定: 決算月、売却時期/額、直営/FC店舗数、ロイヤリティ
- 現状: 直営/FC店舗数、売上、原価率、人件費比率、営業利益/率、FL比、施術単価、人員
- キャッシュポイント想定: 加盟金、研修費、ロイヤリティ、仕入れ、システム、機械代
- 直営出店費用: 物件取得〜エアコンまで10項目 + 合計
- FC出店費用 / FC店モデル図・経営計画 / 営業時間
- 施策アクション: ①ビジネスモデル（成功モデル分析 詳細7項目）〜⑦FC加盟店募集
- ビジョン・ミッション / バリュー / スローガン
- フランチャイズ展開: 募集と選定、サポート体制、継続的な改善
- ブランディングガイドライン: 20項目

#### ヒアリング②タブ（コンセプト設計続き）
- ブランド化戦略 / FC募集契約書
- マニュアルガイドライン: 13項目（目的と範囲〜付録）
- 事業計画: 市場調査、SWOT分析、財務計画
- 法務・ブランド・オペレーション: 法人設立、契約書整備、ロゴ、マーケティング、業務マニュアル、研修、ITシステム

#### 営業資料タブ（FC募集営業資料の構成 41項目）
マニュアルの【営業資料フォーマット】に対応。6グループ構成:
- 導入・つかみ: タイトル、なぜFCを募集するのか、ブランドの強み、成功の定義、ロードマップ
- 会社・市場: 会社概要、MVV、業界市場状況、顧客/スタッフから見るニーズ、出店する魅力
- 業界課題と成功要因: 業界がうまくいかない理由、オーナーの悩み、成功の秘訣
- ビジネスモデル・技術: 売上/集客/採用の仕組み、技術紹介、他社比較、店舗イメージ、施術BA、口コミ等
- 収益・費用: 経営パッケージ、収益シミュレーション、開業費用、売上アップ計画、オーナーの声
- サポート・加盟条件・クロージング: 本部支援、役割分担、加盟条件、キャンペーン価格、OPENまでの流れ

### 既存コンテンツセクション

| セクション | 内容 |
|-----------|------|
| **広告クリエイティブ** | 画像カードギャラリー |
| **広告運用設計** | Markdownコンテンツ |

## 技術仕様

- **データ永続化**: localStorage（プレフィックス `{{STORAGE_PREFIX}}-`）。キー: `-carte-data` / `-gantt-tasks` / `-minutes` / `-manuals` / `-deliverables` / `-logins` / `-phase`（現在フェーズ1〜5）/ `-carte-saved-at`（カルテ最終保存時刻）
- **デザイン**: アイボリー&ゴールド（高級ホテル風ライトラグジュアリー）。白カード + ベージュゴールド罫線 + 柔らかい影、見出しはセリフ体
- **フォント**: Noto Sans JP（本文）+ Noto Serif JP（見出し）+ Inter（Google Fonts CDN）
- **サイズ**: 約100KB（単一HTML、外部依存なし）
- **デプロイ先**: surge.sh 推奨

## プレースホルダー一覧

テンプレートHTML内の以下のプレースホルダーをクライアント情報に置換する:

| プレースホルダー | 説明 | 記入例 |
|---------------|------|-------|
| `{{BRAND_NAME}}` | ブランド名（サイドバー・タイトルに表示） | サンプルブランド |
| `{{CLIENT_COMPANY}}` | 法人名 | 株式会社サンプル |
| `{{CLIENT_CEO}}` | 代表者名 | 山田 太郎 |
| `{{CLIENT_COMPANY_KANA}}` | 法人名カナ | カブシキガイシャサンプル |
| `{{CLIENT_CEO_KANA}}` | 代表者名カナ | ヤマダ タロウ |
| `{{CLIENT_INDUSTRY}}` | 業種 | 飲食業・FC展開 |
| `{{BRAND_DESCRIPTION}}` | ブランド説明（フッター用） | ○○専門店「△△」FC事業部 |
| `{{STORAGE_PREFIX}}` | localStorage接頭辞（英数小文字） | sample |
| `{{DEPLOY_DOMAIN}}` | デプロイ先ドメイン | sample-dashboard.surge.sh |
| `{{LP_URL}}` | FC募集LPのURL | https://sample-fc-lp.surge.sh |
| `{{THANKS_URL}}` | サンクスページのURL | https://sample-fc-thanks.surge.sh |
| `{{SEMINAR_URL}}` | セミナー案内ページのURL | https://sample-fc-seminar.surge.sh |
| `{{PROPOSAL_URL}}` | 個別面談用提案書のURL | https://sample-fc-proposal.surge.sh |

LP等が未制作の案件では、URL系プレースホルダーには空文字ではなく `#` を入れておく（リンク切れ防止）。制作完了時にダッシュボードを再生成するか直接置換する。

## 使い方

### Step 1: テンプレートをコピー

```bash
cp templates/dashboard-template.html /path/to/client/project/dashboard.html
```

### Step 2: プレースホルダーを置換

Pythonスクリプトまたはテキストエディタで、上記プレースホルダーをクライアント固有情報に一括置換する。

```python
import re

with open('dashboard.html', 'r') as f:
    html = f.read()

replacements = {
    '{{BRAND_NAME}}': 'クライアントのブランド名',
    '{{CLIENT_COMPANY}}': '株式会社クライアント',
    '{{CLIENT_CEO}}': '代表者 氏名',
    '{{CLIENT_COMPANY_KANA}}': 'カブシキガイシャクライアント',
    '{{CLIENT_CEO_KANA}}': 'ダイヒョウシャ シメイ',
    '{{CLIENT_INDUSTRY}}': '業種・事業内容',
    '{{BRAND_DESCRIPTION}}': '○○専門店「△△」FC事業部',
    '{{STORAGE_PREFIX}}': 'clientid',
    '{{DEPLOY_DOMAIN}}': 'clientid-dashboard.surge.sh',
    '{{LP_URL}}': '#',        # 制作済みなら実URL
    '{{THANKS_URL}}': '#',
    '{{SEMINAR_URL}}': '#',
    '{{PROPOSAL_URL}}': '#',
}

for key, val in replacements.items():
    html = html.replace(key, val)

with open('dashboard.html', 'w') as f:
    f.write(html)
```

### Step 3: コンテンツのカスタマイズ

案件に応じて以下をカスタマイズ:
- 既存セクション（広告、LP、セミナー等）のカード内容
- ガントチャートのデフォルトタスク
- マニュアルのプリセット項目
- 成果物管理のチェックリスト項目
- ログイン情報のデフォルトサービス

### Step 4: デプロイ

```bash
mkdir -p /tmp/dashboard-deploy
cp dashboard.html /tmp/dashboard-deploy/index.html
npx -y surge /tmp/dashboard-deploy {{DEPLOY_DOMAIN}}
```

## カラーパレット（アイボリー&ゴールド）

CSS変数名は歴史的経緯で維持している（`--white` はテキスト主色＝濃茶、`--forest` は淡ベージュ面）。値だけ差し替えれば別テーマ化できる。

```css
--bg:      #f6f1e6    /* アイボリー（ページ背景） */
--card:    #ffffff    /* カード面 */
--cream:   #fdfbf5    /* サイドバー背景 */
--forest:  #f1e9d4    /* 淡ベージュ面（テーブルヘッダ等） */
--border:  #e2d8c2    /* ベージュゴールド罫線 */
--white:   #2a2519    /* メインテキスト（濃茶） */
--gray:    #8c8266    /* サブテキスト（グレージュ） */
--gold:    #a8862f    /* アクセントゴールド */
--gold-dim: rgba(168,134,47,0.08)  /* ゴールド淡背景 */
--green:   #2f7d4f    /* 成功/完了 */
--red:     #b3443a    /* エラー/遅延 */
--blue:    #2f5fa8    /* リンク/予定 */
--orange:  #b5762a    /* 警告/進行中 */
```

デザインディテール: セクション見出し下の40px×2pxゴールド罫線、アクティブタブ・ナビのゴールド下線/左ボーダー、プライマリボタンは濃茶×クリーム文字（ゴールド塗りにしない）、input focus時はゴールドリング。

## 参照ファイル

- `templates/dashboard-template.html` — 生成元テンプレート

## 参考実装

- 初回導入実績あり（surge.sh にてデプロイ済み）
- テンプレートは汎用化済み（実クライアントデータは含まない）。議事録・ガントタスクのデフォルトは構造を示すサンプルであり、案件の実データはStep 3で投入する
