# タングルシード ブログ記事制作ルール
## 〜 30年キャリアのライター × 敏腕編集者の制作プロセス

---

## インプット
- `TOPIC`: 記事のテーマ（例：「ゼンタングルで不眠症を改善する方法」）
- `SLUG`: URLスラッグ（例：`zentangle-insomnia`）
- `CATEGORY`: カテゴリ（例：メンタルケア、初心者向け、活用術、テクニック、etc.）
- `DATE`: 公開日（例：2026.04.07）

---

## フェーズ1：編集会議（構成設計）

### 1-1. 読者の「検索意図」を解剖する

記事を書き始める前に、必ず問いに答えること。

| 問い | 分析内容 |
|-----|---------|
| 顕在ニーズ | このキーワードで検索した人が「今すぐ知りたいこと」は何か？ |
| 潜在ニーズ | その人が「本当は解決したい悩み・不安・願望」は何か？ |
| 誰が読む？ | 年齢・性別・状況・感情状態を具体的にイメージする |
| 読んだ後の状態 | この記事を読み終えた後、読者はどんな気持ちになるべきか？ |

**例（不眠症の記事）：**
- 顕在ニーズ：「眠れない 対策」と検索した
- 潜在ニーズ：薬に頼らず、自然に眠れる方法を探している。「また眠れない夜を過ごしたくない」という恐怖がある
- 読者像：40代・仕事のストレスで寝付けない人。夜中にスマホを見てしまっている
- 読後の状態：「これなら今夜から試せる」という希望と、具体的な行動への意欲

### 1-2. 競合記事にない「独自の視点」を一つ決める

検索上位の記事が書いていない、タングルシードだからこそ語れる視点を必ず一つ入れる。

**タングルシード固有の強み（E-E-A-T = 経験・専門性・権威性・信頼性）:**
- ふるはし美鳥はCZT30（ゼンタングル認定講師第30期）
- 8年間・累計4万人への指導実績
- がん患者・NPO現場での心のケア経験
- 「ゼンタングルには失敗がない」という哲学を体現した現場の声

これらを活用して「他の誰も書けない一次情報」を必ず本文に盛り込む。

## フェーズ2：記事設計（ライターへの発注書）

### 2-1. タイトルの設計ルール

| 要素 | ルール |
|-----|-------|
| 長さ | 30〜35文字（スマホで切れない長さ） |
| キーワード | メインキーワードを前半に置く |
| 感情 | 読者の「痛み」か「欲求」に刺さる言葉を入れる |
| 数字 | 使える場合は数字を入れる（「3つの理由」「15分で」等） |

**NG例：** 「ゼンタングルについて」  
**OK例：** 「眠れない夜の処方箋。不眠症に効くゼンタングル3つの理由」

### 2-2. meta descriptionのルール

- **文字数：** 110〜120文字（120字厳守）
- **構成：** ①読者の痛み or 共感 → ②記事で得られること → ③行動を促す言葉
- キーワードを**冒頭100字以内**に自然に含める
- 「詳しく解説」「紹介します」で終わらない。"誰の・何の悩みを・どう解決するか" を具体的に

### 2-3. 見出し（H2/H3）設計ルール

**H2（大見出し）の原則：**
- 4〜6個（多すぎると散漫になる）
- H2だけ読めば記事全体のストーリーが分かるレベルまで具体化する
- 「〜について」で終めない。読者の言葉で書く
- キーワードまたは共起語をH2のどこかに自然に含める

**H3（小見出し）の原則：**
- 各H2に2〜3個目安
- H2の問いに対する「答え」または「具体例」を提示する形で設計する

**推奨する記事の骨格（PREP変形型）：**
```
【導入】（共感 → 問題の深刻さ → この記事で解決できる約束）
 H2: 問題・悩みの背景を深掘り（なぜ困っているのか）
 H2: なぜゼンタングルが有効なのか（メカニズム・理由）
 H2: 具体的な方法・実践内容
 H2: タングルシード独自の視点・体験（一次情報。競合に書けない部分）
 H2: よくある疑問・応用（FAQや関連情報）
【まとめ + CTA】（行動への背中を押す）
```

## フェーズ3：執筆ルール（ライターの鉄則）

### 3-1. 書き出し（リード文）の法則

最初の3文で読者を引き込む。構成は以下の順に：

1. **読者の状況への共感**（「〜でお悩みではないでしょうか」ではなく、情景描写で）
2. **問題の重さを示す**（データ・数字、または「あなただけじゃない」という承認）
3. **この記事を読むと何が得られるか**（具体的・断言する）

> ❌ NG例：「今日は不眠症とゼンタングルについてご紹介します。」  
> ✅ OK例：「布団に入っても、頭の中が止まらない。そんな夜を、あなたも経験したことがあるのではないでしょうか。厚生労働省の調査によれば、日本人の5人に1人が睡眠に問題を抱えています。この記事では……」

### 3-2. 本文の文体・トーン

| 原則 | 詳細 |
|-----|------|
| 一人称 | 「私」（古橋美鳥として語る）|
| 語りかけ | 「あなた」を主語にした文章を意識的に入れる |
| 文の長さ | 1文を40〜60字を目安に。長文が続かない |
| 段落 | 3〜5行で改行。スマホで読みやすいリズム |
| データ | 数字・研究・エビデンスを根拠として使う |
| 専門性 | 難しい用語はその場で簡潔にほぐして説明する |
| 禁止語 | 「〜と思います」「〜でしょう」は極力避ける。断言する |

### 3-3. 「一次情報」の盛り込み方

以下のいずれかを必ず1箇所以上盛り込む：

- 「8年間の現場で、〇〇という場面をよく目にします」
- 「累計4万人にゼンタングルを届ける中で気づいたのは……」
- 「NPO活動でがん患者の方々と向き合ってきた私が感じる……」
- ワークショップ参加者の（匿名・改変した）具体的な反応・言葉

### 3-4. 文字数の基準

| 種別 | 文字数 |
|-----|-------|
| 標準的な記事 | 2,500〜3,500字 |
| 深掘り系（ハウツー・ガイド） | 3,500〜5,000字 |
| コラム・エッセイ系 | 1,500〜2,500字 |

### 3-5. CTAの書き方

「無料プレゼントを受け取る」ボタンの直前の文章は以下の型で：

1. 記事で伝えたことを一言でまとめる（結論の再確認）
2. 読者の「次の行動」への欲求を刺激する（「もっと知りたい」「試してみたい」）
3. 無料という心理的ハードルの低さを強調
4. 具体的に何がもらえるか（PDF・動画など）

## フェーズ4：SEO技術設定

### 4-1. キーワード配置チェックリスト

- [ ] タイトル（H1）にメインキーワードを含める
- [ ] meta descriptionにメインキーワードを含める
- [ ] 最初のH2にキーワードまたは共起語を含める
- [ ] 本文の最初の100文字以内にメインキーワードを含める
- [ ] 画像のaltにキーワードを自然に含める
- [ ] canonical URLが正しく設定されている
- [ ] `<title>`タグが32文字以内（タイトル|タングルシード含め）

### 4-2. 内部リンクの設計

各記事に必ず以下の内部リンクを自然な形で盛り込む：

| リンク先 | タイミング |
|---------|----------|
| タングル図鑑（`/library.html`） | パターンに言及したとき |
| 関連ブログ記事（`/blog/*.html`） | 関連するトピックに触れたとき |
| 法人向けページ（`/corporate.html`） | ビジネス・福祉施設の話をしたとき |
| 無料プレゼント（`/gift.html`） | CTAで必ず |

### 4-3. 見出し番号ルール

- 本文中のH2には「1. 2. 3.」と番号を振る（Googleが目次として認識しやすい）
- ただし「〜するための3つの理由」のようにタイトル・H2で数字を使っている場合は重複しないよう調整

## フェーズ5：編集長チェック（公開前の最終確認）

公開前に以下の全項目を確認すること：

### ライティング品質チェック
- [ ] リード文で読者の「あるある」を掴んでいるか
- [ ] タングルシード固有の一次情報が最低1箇所含まれているか
- [ ] 「〜だと思います」「〜でしょうか」という弱い表現を断言に変えたか
- [ ] CTAの前に「なぜ今行動すべきか」の文章があるか
- [ ] 読み終えた後の読者の感情をイメージして、ラストの段落を書いているか

### SEOチェック
- [ ] タイトルが32文字以内でキーワードが前半にあるか
- [ ] meta descriptionが110〜120字か
- [ ] 画像のaltが適切か（空でない、キーワードを含む）
- [ ] 内部リンクが最低2箇所あるか
- [ ] canonicalが正しいか

### 技術チェック
- [ ] HTMLの構造が`_template.html`の形式と一致しているか
- [ ] GA4タグ（G-B5MMYK9SCY）が残っているか（テンプレート由来。消えていたら復元）
- [ ] blog/index.htmlに記事カードが追加されているか（最新記事を一番上に）
- [ ] sitemap.xmlに新記事のURLが追加されているか
- [ ] 画像が`images/blog/[SLUG].jpg`に保存されているか

## フェーズ6：デプロイ

### 記事用画像の生成

記事テーマに合ったリアルな写真風の画像を生成する（ゼンタングルの図案ではなく、情景・人物・手元など）。

**プロンプト例（TOPICに合わせて調整）：**
```
Soft lifestyle photography style. [TOPICのシーンを具体的に描写].
Warm natural light, minimal Japanese interior or calm outdoor setting.
No faces clearly visible or hands-only close-up. Film grain aesthetic. Square format.
```

**例：**
- 不眠症 → ベッドと間接照明、手元にノートとペン
- 自律神経 → 縁側や窓辺で瞑想する後ろ姿
- 認知症・高齢者 → お茶と一緒に手元でペンを持って書いているシーン
- ストレス → 自然の中や朝の静かな室内

生成した画像を `/Users/hiroshi/cursor/projects/tangleseed-website/images/blog/[SLUG].jpg` として保存する。

### HTMLファイルの作成

`/Users/hiroshi/cursor/projects/tangleseed-website/blog/_template.html` をコピーして `blog/[SLUG].html` を作成し、プレースホルダーをすべて置換する。

テンプレートにはGA4タグ（G-B5MMYK9SCY）が設置済みのため、新記事にも自動で含まれる。置換の際に削除しないこと。

### blog/index.htmlへの記事カード追加

最新記事を一番上（`<div class="blog-grid">` の直後）に追加する：

```html

<article class="blog-card">
    <div class="blog-card__image">
        <img src="../images/blog/[SLUG].jpg" alt="[IMAGE_ALT]" loading="lazy">
    </div>
    <div class="blog-card__content">
        <div class="blog-card__meta">
            <span>[DATE]</span>
            <span>[CATEGORY]</span>
        </div>
        <h2 class="blog-card__title">[TITLE]</h2>
        <p class="blog-card__excerpt">
            [DESCRIPTION（120字以内）]
        </p>
        <a href="/blog/[SLUG].html" class="blog-card__link">続きを読む →</a>
    </div>
</article>
```

### sitemap.xmlへのURL追加

`/Users/hiroshi/cursor/projects/tangleseed-website/sitemap.xml` の `</urlset>` 直前に新記事のエントリを追加する：

```xml

    <loc>https://tangle-seed.co.jp/blog/[SLUG].html</loc>
    <lastmod>[YYYY-MM-DD]</lastmod>
    <changefreq>monthly</changefreq>
```

### FTPアップロード（これが本番公開）

FTP認証情報は `/Users/hiroshi/cursor/ftp-uploader/config.json` から読む。ただし同ファイルの `remote_directory` は fproduction.co.jp 用なので使わず、アップロード先は必ず `/tangle-seed.co.jp/public_html` を明示する。

```bash
python3 - <<'EOF'
import json, ftplib
from pathlib import Path

SLUG = "[SLUG]"  # ← 置換
SITE = Path("/Users/hiroshi/cursor/projects/tangleseed-website")
REMOTE_ROOT = "/tangle-seed.co.jp/public_html"  # config.jsonのremote_directoryは使わない

files = [
    (SITE / f"blog/{SLUG}.html",       f"{REMOTE_ROOT}/blog/{SLUG}.html"),
    (SITE / "blog/index.html",         f"{REMOTE_ROOT}/blog/index.html"),
    (SITE / "sitemap.xml",             f"{REMOTE_ROOT}/sitemap.xml"),
    (SITE / f"images/blog/{SLUG}.jpg", f"{REMOTE_ROOT}/images/blog/{SLUG}.jpg"),
]

cfg = json.load(open("/Users/hiroshi/cursor/ftp-uploader/config.json"))
ftp = ftplib.FTP()
ftp.connect(cfg["host"], cfg.get("port", 21))
ftp.login(cfg["username"], cfg["password"])
ftp.set_pasv(cfg.get("passive_mode", True))
for local, remote in files:
    d, name = remote.rsplit("/", 1)
    ftp.cwd(d)
    with open(local, "rb") as f:
        ftp.storbinary(f"STOR {name}", f)
    print("OK", remote)
ftp.quit()
EOF
```

トップページなど他のHTMLも変更した場合は、同様に `files` に追加してアップロードする。

### 公開確認

アップロード直後に本番URLで表示を確認する（ブラウザキャッシュ回避のためシークレットウィンドウ推奨）：
- `https://tangle-seed.co.jp/blog/[SLUG].html` — 記事本体が表示される
- `https://tangle-seed.co.jp/blog/` — 一覧の一番上に新記事カードが出る
