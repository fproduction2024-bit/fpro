# AI向け指示書：タングル図鑑の本番化改善

あなた（AIアシスタント）は、株式会社タングルシードの公式サイトに載せる「タングル図鑑」のデータを、本番公開できる品質に改善します。
このフォルダの持ち主は、ゼンタングルのコンテンツ制作者（認定講師クラス）です。**持ち主の判断・知識が最優先**です。あなたは調べ物・文章化・整形・形式チェックを担当してください。

作業を始める前に、この指示書を最後まで読んでください。

---

## 1. ゴール

`data/patterns.ts` に入っている全154タングルについて、次の状態にすること。

- 名前・読み・説明・描き方手順が**事実として正しく**、日本語として自然で、初心者に役立つ
- 各タングルに**権利的に問題のない画像**がある（持ち主が描いたもの）
- 動画は**そのタングルを実際に扱っている、使用してよい動画**だけが紐づいている
- 形式チェック（`node tools/build_check.mjs`）でエラー0件

一度に全部終わらせる必要はありません。下の「優先順位」の順に、10〜20件ずつ進めてください。

## 2. フォルダ構成

```
README.md                 持ち主向けの説明（読まなくてよい）
AI_INSTRUCTIONS.md        この指示書
tangle_zukan_check.html   人が見るチェックシート（ツールで自動生成。手で編集しない）
CHANGELOG.md              変更記録（あなたが毎回追記する）
data/patterns.ts          ★編集対象。図鑑の全データ
data/reference_urls.md    TanglePatterns.com の参照URL調査結果（ID対応）
images/patterns/          ★画像置き場。ファイル名は <slug>.jpg
feedback/                 持ち主がチェックシートから書き出したCSV（あれば）
tools/build_check.mjs     形式チェック＋チェックシート再生成
tools/zukan_check.template.html  チェックシートのひな形（編集しない）
```

## 3. 作業の手順（毎回この順番）

1. **持ち主のフィードバックを読む**
   `feedback/` に CSV があれば一番新しいものを読む。列は
   `ID, 英名, 日本語名, slug, 難易度, ステータス, (確認項目×7), メモ, 自動フラグ, 参照URL`。
   - ステータス「要修正」＋メモ → メモの指示どおりに直す（最優先）
   - ステータス「削除・統合」 → メモに従う。メモが無ければ削除せず、持ち主に確認する
   - ステータス「OK」 → そのタングルは**変更しない**（明らかな誤字だけは直してよいが、CHANGELOGに書く）
2. **現状を確認する**：`node tools/build_check.mjs` を実行し、形式エラーと自動フラグ件数を見る。
3. **今回の対象を決める**：フィードバック分＋「優先順位」の上から10〜20件。
4. **修正する**：`data/patterns.ts` を編集（ルールは4章・5章）。
5. **検証する**：もう一度 `node tools/build_check.mjs` を実行し、**形式エラー0件**を確認。チェックシートも自動で作り直されます。
6. **記録する**：`CHANGELOG.md` に、対象・変更内容・根拠・未解決事項を追記。
7. **報告する**：持ち主に「何件直したか」「判断してほしいこと」を短く伝え、`tangle_zukan_check.html` を開いて確認してもらう。

Node.js が無い環境では手順2・5を実行できません。その場合は持ち主に Node.js（https://nodejs.org の LTS版）のインストールをお願いするか、4章のルールを目で確認したうえで「形式チェック未実施」とCHANGELOGに書いてください。

## 4. 絶対に守るルール

### データ形式
- `data/patterns.ts` は TypeScript ファイルです。**`patterns` 配列の中身だけ**を編集し、`interface` 定義・ヘルパー関数・ファイル構造は変えない。
- `id` と `slug` は**変えない**（サイトのURLになるため）。名前を直す場合も slug はそのまま。slug変更が本当に必要なら持ち主に確認し、CHANGELOGに明記。
- 新しいタングルを追加する場合：`id` は既存の最大値+1、`slug` は半角英小文字・数字・ハイフンのみ。
- 各フィールド：

| フィールド | 内容 |
|---|---|
| `name` | 英語の正式名（TanglePatterns.com／Zentangle公式の表記） |
| `nameJa` | カタカナ表記。発音に基づく。他のタングルと重複させない |
| `description` | 英語説明。60〜120語。descriptionJa と同じ内容を自然な英語で |
| `descriptionJa` | 日本語説明。5章の書式 |
| `difficulty` | `beginner`（初級）/ `intermediate`（中級）/ `advanced`（上級）のいずれか |
| `category` | 下記の定義済みカテゴリのみ。先頭は `official` |
| `steps` | 3〜7ステップ。`stepNumber` は1からの連番。`instruction`（英）と `instructionJa`（日）両方必須 |
| `youtubeVideoId` | YouTubeの11文字のID。不明・不適切なら**行ごと削除**（空文字にしない） |
| `imageUrl` | 必ず `'/images/patterns/<slug>.jpg'` |
| `createdAt` | 変更しない |
| `tags` | 英小文字・ハイフン区切り。創作者名は `Maria-Thomas` のような形 |

- 定義済みカテゴリ（`categoryTranslations` にあるもの）：
  `official, foundational, organic, geometric, weaving, fill, texture, enhancement, shading, technique, flowing, 3d, illusion, featured, floral, simple, hybrid, grid`
  これ以外（`marine`, `dots`, `playful` など）は、近い定義済みカテゴリに置き換える。どうしても必要な新カテゴリは、持ち主の了承を得てから `categoryTranslations` に日本語訳つきで追加する。

### 事実・権利
- **事実を作らない。** 創作者名・創作年・由来・CZTの経歴などは、確認できた情報だけを書く。確認できないことは書かずに、CHANGELOGの「要確認」に回す。推測を事実のように書かない。
- 確認に使ってよい情報源：Zentangle公式（zentangle.com）、TanglePatterns.com（`data/reference_urls.md` のURL）、創作者本人のブログ・動画、持ち主の知識。
- **文章のコピー・直訳をしない。** TanglePatterns.com などの説明文は著作物です。事実を確認したうえで、自分の言葉で書く。
- **画像をネットから取ってこない・AIで生成しない。** 画像は持ち主が描いて用意したものだけを使う。あなたの役割は、持ち主が `images/patterns/` に入れた画像のファイル名・サイズを整えること。
- 「Zentangle®」は登録商標。説明文で初出時は「ゼンタングル®」と表記してよい（毎回つける必要はない）。
- 動画は、そのタングルを実際に描いている／解説している動画で、持ち主のチャンネル・公式・許諾済みのものに限る。**動画の中身を確認できないなら紐づけない。**

## 5. 内容の書き方

### descriptionJa（日本語説明）
- 長さ：**400〜600字**（空白除く）。チェックシートに字数が表示されます。
- **最初の段落は1〜2文の要約**にする（図鑑一覧のカードと検索結果の説明文に使われるため）。
- その後に見出しつきの段落。見出しは `**見出し**` の形で1行に書く。箇条書きは `- `、番号付きは `1. `。
- 推奨構成（無い情報の見出しは省く）：
  1. 要約（どんな見た目・どんな魅力のタングルか）
  2. `**創作者と背景**`（確認できた範囲で）
  3. `**特徴**`（見た目・技法上のポイント）
  4. `**描き方のコツ**`（初心者がつまずく点、きれいに見せるポイント）
  5. `**組み合わせ・バリエーション**`（相性のよいタングル、変化形）
- お手本：ID 1 Crescent Moon、ID 2 Hollibaugh（ただしこの2件も事実確認の対象です）。
- 文体：です・ます調。やさしく、押し付けない。ゼンタングルの「間違いはない」という考え方を大切に。
- 誇張・医療的効果の断定（「ストレスが治る」等）は書かない。「リラックスして取り組める」程度にとどめる。

### steps（描き方手順）
- 実際にペンで描く動作を、1ステップ1動作で具体的に。「〜を完成させます」のような中身の無いステップは書かない。
- 持ち主のメモに描き方の指示があれば、それを正とする。
- 既存の手順の多くは3ステップの抽象的な内容です。公式の描き方（ステップ図）を確認できたものから書き直す。

### 名前・読み
- `nameJa` は英語の発音に近いカタカナ。公式や日本の認定講師の間で定着した読みがあればそれを優先。
- 判断がつかない読みは持ち主に確認（CHANGELOGの「要確認」へ）。

## 6. 既に分かっている問題（自動チェック・事前調査より）

| 種類 | 対象 | 対応 |

| 画像なし | 151件（あるのは ID 1, 2, 6 のみ） | 持ち主が描いた画像を待つ。届いたら `<slug>.jpg` に整える |
| 動画なし | 55件 | 適切な動画が確認できたものだけ追加 |

## 7. 優先順位

1. `feedback/` のCSVで「要修正」になっているもの
2. 基本8タングル・人気タングル（ID 1〜20）

4. ID 21〜100 の説明文・手順の書き直し
5. ID 101〜160 の実在確認と書き直し

## 8. 持ち主に確認すべきこと（勝手に決めない）

- タングルの削除・統合、slugの変更
- 確認できなかった事実（創作者・年・読み）
- 動画を紐づけてよいか
- 新しいカテゴリの追加

確認事項は作業の最後にまとめて、番号付きの短い質問リストで持ち主に聞いてください。

## 10. 画像ファイルの整え方

- 形式：JPEG、正方形、1200×1200px 推奨（最低800px）、1ファイル500KB以下
- 背景は白（または黒タイルなら黒）で、タイル全体が収まるように
- ファイル名：`<slug>.jpg`（例：`crescent-moon.jpg`）。slugはチェックシートの各タングルに表示されています
- 持ち主が別名で入れた画像は、どのタングルか確認してからリネーム。変換・縮小には使える手段（Python の Pillow、macOS の `sips` など）を使い、元画像は `images/originals/` に残す
